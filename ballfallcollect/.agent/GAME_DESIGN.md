# GAME_DESIGN.md — 游戏设计（当前有效版本）

**设计确定度**：🟢 核心循环 / 操作 / 胜负 / 关卡结构均已拍板，可直接开发

> 本文件只描述**当前有效的设计**。
> 具体数值以 `core/GameTypes.ts` 的 `CFG` 与 `config/LevelConfig.ts` 为准；
> 实现机制与技术约束见 `TECH_NOTES.md`。
> 尚未拍板的设计问题统一列在 `TODO.md`「待用户确认」。

---

## 一、核心定位

竖屏 2D 休闲游戏，750 × 1334，正交相机。

**本质**：一条自动物流流水线，玩家是**调度者**——只决定「何时释放哪个格子」，其余全自动。

---

## 二、玩家操作

**玩家唯一操作 = 点击顶部彩色格子。**

小球、V 槽、轨道、收纳箱**玩家一律不可操作**（不可拖动、不可控速、不可旋转）。
不点击就不会有球出来。

---

## 三、核心循环

```
点击顶部格子 → 该格释放 9 个小球
  ↓ 刚体重力自由下落
落入对应 V 槽并在槽底汇聚
  ↓
自动进入环形轨道，占据一个离散槽位
  ↓ 沿轨道循环运动
经过对应颜色收纳箱 → 自动入箱
  ↓ 该箱累计 3 个
箱子消失，轨道继续运行
```

---

## 四、顶部格子与小球

- 顶部若干**单色**格子，每格含 **9 个**同色小球
- 每个格子下方各有一个 V 型槽（一一对应）
- ColorBlock 真实类型网格来自 `play/config/all_levels_simple_edited.json`；`LevelGrids.json.levels` 每条记录以 `layout` 直接引用其中的字符串 `levelId`，并维护 path 配色、seed 与箱序难度。运行时以 `VSlot/Startgridpos` 为底部中心生成，布局最多 8 列
- 网格水平居中、向上展开；间距为 ColorBlock Prefab 实际节点尺寸 + `CFG.colorBlockGridGap`
- 网格单元使用自然数类型码：`0=空位、1=normal、2=unknown、3=boxes`；代码中由 `ColorBlockType` 数值枚举统一解释
- 空位可位于网格任意位置；所有非空节点必须上下左右连通，颜色由代码运行时分配
- 网格最底行初始可点击；其他 ColorBlock 锁定，只有上/下/左/右相邻格被点击后才解锁
- `unknown` 类型禁止出现在最底行；解锁前显示 `Unknown` 和 Background，Background 保持 Prefab 原色而不赋玩法颜色，Slots 隐藏；邻格点击解锁时隐藏 Unknown、恢复实际颜色，并播放标准解锁动画
- `boxes` 使用 `ColorBlockBoxes.prefab`，不得出现在最底行，直接下方必须是 normal/unknown；下方格子成功点击时向该位置派发下一个 ColorBlock
- Boxes 内待派发 ColorBlock 在关卡初始化时就必须分配颜色并计入总球数/收纳箱容量；`Num(Label)` 的正整数为派发数，留空默认 3
- 任何类型或来源的 ColorBlock 在所有小球成功释放后，统一播放根节点缩小退场动画再隐藏，不保留空 Background
- 锁定格显示 Prefab 的 `Lid`，解锁后隐藏；Lid 初始化颜色跟随该 ColorBlock
- ColorBlock 解锁时播放一次自身缩放脉冲，同时 Lid 平滑缩小至消失
- 轨道外（含尚在 ColorBlock 前置动画中）的已释放批次最多累计 `CFG.maxUntrackedBallBatches × CFG.ballsPerBlock`（当前 4×9=36 球）；整批点击会超过上限时拒绝释放并飘字“小球太多了”
- 点击后该格**逐个连续释放** 9 球（同帧生成会重叠，Box2D 会剧烈弹开）
- 释放中的格子不响应重复点击；格子放空后统一缩小并隐藏根节点

## 五、V 型槽

- 每格下方一个，承接下落小球并使其在槽底汇聚
- **由用户在编辑器摆放**（`VSlot.prefab`），位置 / 角度 / 尺寸 / 数量全由用户决定
- **无容量上限**，球可堆积等待
- 需要额外引导球到轨道入口时，由用户自行摆放斜板，**代码不生成任何汇流结构**

---

## 六、小球物理

小球具有 2D 刚体 + 重力，自由下落进 V 槽。

上轨后**关闭物理改由脚本定位**，入箱用 Tween —— 即「混合驱动」，
理由与切换点见 `TECH_NOTES.md` 5.1。

---

## 七、环形轨道与 24 槽位

- V 槽下方有**一个**环形轨道（跑道形：上下直线 + 左右半圆），持续循环运动
- **24 个固定离散槽位**，按路径弧长均匀分布
- 每球占一个槽位，最多同时容纳 **24 个**，**不允许塞入第 25 个**
- 轨道位置不写死：入口 = 场景中 `EntranceGate` 节点位置

---

## 八、小球进入轨道

- 轨道顶部有入口捕获区，球落入且有空槽经过入口时自动吸附入槽
- 入口下方有挡板，无空槽时小球**物理堆积等待**，不会掉出
- 多球等待时**先到先入**

---

## 九、颜色与收纳箱对应关系

关卡生成时即算好全部对应关系：格子颜色 → 球颜色 → 箱颜色 → 每色所需箱数。
**玩家只负责决定释放顺序，不决定颜色对应关系。**

### 9 / 3 关系

每箱容 3 球、每格 9 球 ⇒ **每种颜色的格子数 × 3 = 该色箱数**。
（等价约束：每种颜色的箱数必须是 3 的倍数）

---

## 十、收纳箱

- 位于轨道下方，每箱对应一种颜色，位置固定
- 每箱最多 **3 个**同色球，收满即完成并消失
- 球运动到**对应颜色**箱上方时自动离开轨道入箱

### 队列机制（重要设计）

- **固定 4 列**，每列一个独立队列；列的 X 由收纳箱系统自己定义，
- 每个收纳箱固定 3 个可编辑槽位；每个 Slot 下的 `BallVisual` 是小球最终飞入位置和收纳后的显示，Slot 自身只表现槽外观
- 后排箱子补位进入第一排的 Tween 期间不可收球，只有补位完成后才开放接收
  **与顶部格子完全无关**（不读格子坐标、不随格子数量变化）
- **每列只有第一行可以收球**，其余行等待（外观压暗）
- 某箱收满消失后，**只有它所在列**向上补位；箱子分配到某列后**永不跨列移动**
- **第一行没有对应颜色时，球继续沿轨道运行**，后排同色箱不得「抢球」
  → 这是玩家点击策略性的来源
- 四列中所有收纳箱始终显示，不再按关卡隐藏后排行；只有每列第一行允许收球

> ⚠️ 该机制使「阻塞失败」真实可能：第一行颜色与放出的球不匹配时，
> 球会持续占用槽位直至判负。这是**预期的策略压力，不是 bug**。

---

## 十一、胜负条件

| 结果 | 条件 |
|---|---|
| **胜利** | 所有格子的小球全部进入对应收纳箱 |
| **失败** | 轨道 24 槽全部占满，且所有非空列中已完成补位的第一行箱子都无法匹配轨道内任何小球，持续超过宽限时间 |

失败判定带**宽限期**。第一行箱子正在补位或完成动画时暂停判负；空列不参与匹配判断。
满槽本身是瞬时常态，只有形成当前首箱颜色死锁并持续超过宽限时间才失败。

## 十二、关卡结构

**地形（空间）与规则（玩法）严格分离：**

| | 内容 | 谁决定 |
|---|---|---|
| `VSlot.prefab` | V 槽、`EntranceGate`、网格底部中心 `Startgridpos`、收纳箱第一行中心 `BoxCollectPos` | 用户在编辑器摆放 |
| `play/config/all_levels_simple_edited.json` | ColorBlock 真实类型网格布局库 | 布局事实源 |
| `play/config/LevelGrids.json` | 1000 关的直接布局引用、path 配色、seed 与箱序分段扰乱比例 | 关卡规则事实源 |
| `LevelDef`（`config/LevelConfig.ts`） | JSON 解析后的运行时类型与生成规则 | 代码 |

- 关卡只有一种生成逻辑，无需配置 mode：最底行 ColorBlock 的 `path=1`，其余可见格按四方向相邻最短解锁路径逐层递增，Boxes 内格子按派发顺序接在目标格 path 之后
- `blockColor` 使用 `[累计百分比上限, [最小颜色id, 最大颜色id]]`，按 path 升序后的百分位分段；生成结果再映射回原运行时索引，不改变解锁或 Boxes 派发关系
- 收纳箱先按 path 排序后的 `blockColors` 倒序生成，使更晚解锁的 ColorBlock 对应更靠前的箱子
- `boxShuffleSegments=[]` 表示完全保留倒序爽感排布；非空数组合计必须为 1，每段只在内部用本关 seed 洗牌，以分段大小控制难度
- 每关加载时由 `LevelValidator` 校验，不通过**禁止进入游戏**
- 关卡难度杠杆：格子数量与布局、颜色种类、箱子列颜色顺序、洗牌程度。
- `trackSpeed` 与 `loseGraceTime` 是全局手感参数，只在 `CFG` 维护，不由关卡 JSON 覆盖。
- 本关所有 ColorBlock 都至少点击一次后，轨道速度立即变为当前关卡基础速度的 2 倍。
- `releaseInterval` 是全局出球节奏，只在 `CFG` 中维护，不由关卡配置覆盖。

**做新关卡 = 在 `LevelGrids.json.levels` 增加记录并用 `layout` 填写外部布局 ID；禁止再把 grid 复制进规则表或维护并行布局数组。**

## 十三、第一版范围

**做**：上述核心机制；Ball、ColorBlock、VSlot、CollectBox 与动态 Popup 均使用可编辑 Prefab，正式视觉逐步替换原型表现。

**明确不做**：UI 美化、音效、粒子特效、道具、特殊球、复杂关卡生成、
广告、存档、引导、商店、网络功能。

**目标**：验证核心循环能否稳定运行，不追求美观。
